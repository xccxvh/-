# Velocity return control references · 2026-11-26

The three source revisions illustrate three different ways to obtain a damping signal. Run 174123 supplies local evidence for the direction of motion and the age of a position sample at the controller. Its short sequence of changing PWM commands leaves the acceleration per tick and mechanical response delay unresolved.

## TSummersLab/open-ball-beam

The Arduino `interface` sketch selects a linear observer and incremental state feedback. It estimates two physical states with `(A − LC)x + Bu + L(error)`, using observation minus setpoint and the preceding controller action. It appends integrated error and the previous action, then adds `Kz` to the action. A selectable PID estimator separately smooths error and its fixed-period difference. In the Python PID implementation the saturation hold is configurable. [Arduino selection](https://github.com/TSummersLab/open-ball-beam/blob/58cb13670a6883f4b089383d6dd89b72675bc3c6/ballbeam/arduino/interface/interface.ino#L52-L55) · [Linear observer](https://github.com/TSummersLab/open-ball-beam/blob/58cb13670a6883f4b089383d6dd89b72675bc3c6/ballbeam/arduino/interface/src/Estimator.cpp#L21-L59) · [PID alternative](https://github.com/TSummersLab/open-ball-beam/blob/58cb13670a6883f4b089383d6dd89b72675bc3c6/ballbeam/arduino/interface/src/Estimator.cpp#L85-L110) · [Incremental control](https://github.com/TSummersLab/open-ball-beam/blob/58cb13670a6883f4b089383d6dd89b72675bc3c6/ballbeam/arduino/interface/src/Controller.cpp#L12-L24) · [Python PID error update](https://github.com/TSummersLab/open-ball-beam/blob/58cb13670a6883f4b089383d6dd89b72675bc3c6/ballbeam/common/controller.py#L57-L72)

The sketch checks elapsed milliseconds against a 20 ms period and performs one update when due. The estimator uses the configured period even if the loop runs late. The pulse issuer clips at the servo limits and flags either limiting value. On the following update the estimator holds the error sum when that flag is set. The incremental controller still carries its internally requested action. The gains in this path are fixed across the trajectory. ## giannispoliths/Ball-and-Beam-PID-CONTROL

In Version 2 the host scales the center of the largest qualifying HSV contour and exponentially smooths position with weight 0.4 on the newest sample. For each qualifying detection it transmits position and three operator-selected gains. The initial host sliders send Ki = 0. The Arduino forms the derivative by differencing deadbanded position error over elapsed packet-processing time. A detection gap therefore changes the derivative interval and can also extend the interval used for integration. Gain changes come from the sliders. [Filter constants](https://github.com/giannispoliths/Ball-and-Beam-PID-CONTROL/blob/a48ecdb68c2b4212e313dde67f4056d61f2d7a47/Version_2_Live_Tuning/2_PID_TrackBars_Live_Control.py#L9-L13) · [Selection and transmission](https://github.com/giannispoliths/Ball-and-Beam-PID-CONTROL/blob/a48ecdb68c2b4212e313dde67f4056d61f2d7a47/Version_2_Live_Tuning/2_PID_TrackBars_Live_Control.py#L29-L59) · [Packet handling and timing](https://github.com/giannispoliths/Ball-and-Beam-PID-CONTROL/blob/a48ecdb68c2b4212e313dde67f4056d61f2d7a47/Version_2_Live_Tuning/2_upgradedsketchchangingPID_copy_20260304095716.ino#L40-L81)

The sketch clamps the accumulated error to ±30 before multiplying by Ki. It independently clips the integer servo command to center 68 ±30 degrees, as defined by the executable constants. Inside the 0.15 error deadband it retains the accumulated integral. The output clamp supplies no tracking correction to that integral. ## harsharan-r/ball-balancing-table

The balance thread uses independent constant-velocity Kalman filters for x, y and apparent radius. It predicts using elapsed loop time and corrects only when the camera frame ID changes. On stale input it resets PID history, commands the ready pose and arranges to initialize the filters on the next valid frame. Roll and pitch use estimated velocity directly for damping. The explicit x/y lookahead is set to zero. [Filter equations](https://github.com/harsharan-r/ball-balancing-table/blob/fe5a30ecb7fa37d2f6b00f9d8abfa28a839a7042/src/control/kalman_filter/kalman_filter.cpp#L10-L47) · [Stale-input handling and frame gating](https://github.com/harsharan-r/ball-balancing-table/blob/fe5a30ecb7fa37d2f6b00f9d8abfa28a839a7042/src/control/balance_controller/balance_controller.cpp#L175-L233) · [Control inputs](https://github.com/harsharan-r/ball-balancing-table/blob/fe5a30ecb7fa37d2f6b00f9d8abfa28a839a7042/src/control/balance_controller/balance_controller.cpp#L235-L278)

The thread sleeps for a configured 10 ms after processing. PID integration uses that nominal interval. Its optional anti-windup rule clears the integral inside a small error band. Output clipping happens separately, so a sustained large error can continue accumulating at the output limit. The shipped configuration sets all three Ki values to zero. The code also exposes low-speed derivative scaling, but the shipped multipliers are all 1.0. These settings give fixed roll/pitch damping in the reviewed configuration.
