# Nano → G3519 静态位置反馈

本次使用正式 C 路径、专属 points 标定和 UART0 二进制协议。小车静止，操作员确认板端为 UART/IDLE。启动 Nano 的控制有效位置发送后，仍需 G3519 本地操作才能进入 AUTO。

## 实际运行命令

在 Nano 的独立部署目录运行。驱动为 CMSIS-DAP 虚拟串口，实际设备为 `/dev/ttyACM0`。临时 ACL 在重新插拔后可能需要重新设置。

```bash
cd ~/static_control_Oj24BU/Jetson
export OPENBLAS_CORETYPE=ARMV8 OPENBLAS_NUM_THREADS=1
port=/dev/serial/by-id/usb-wch.cn_CH32_CMSIS-DAP_B7AD8F061FFECDEFG-if01
# 监测模式，bit0 始终为零。每次启动请使用独立标签。
python3 -B main.py --config config_static_control_c.json --serial "$port" --label monitor
# 控制反馈模式。现场先确认 G3519 UART/IDLE、目标 0 和位置符号，再由板端本地使能。
python3 -B main.py --config config_static_control_c.json --serial "$port" --uart-enable-valid --label o_return
```

两条命令分次运行。Ctrl-C 退出时尽力发送一帧无效测量，通信中断由板端超时保护。相机、标定或视觉失效时协议位立即反映当前测量状态。标定有效时 bit1 可独立为 1。真实默认监测试验共发出 61 帧，其中 55 帧携带可读的厘米位置，所有帧 bit0 均为 0。

## 时间戳与双向链路

Nano 上的 V4L2 缓冲标记为 Monotonic、Start-of-Exposure。OpenCV 4.1.1 的 POS_MSEC 反映同一流的驱动时间，故意停读 200 ms 后读到的旧帧年龄为 199.4 ms。正式入口每次打开前探查同设备同格式，逐帧保留读完时间和经核验的驱动时间，通过单槽队列与图像一起消费。控制帧的毫秒时间戳取经核验的 SOE；在本机计算年龄，来源未验证时控制有效位为零。Nano 收完图像的时间仍单独存在视觉日志。

初次监测 80 帧时，只有 13 帧能在曝光后 100 ms 内生成结果，年龄中位为 112.33 ms。C 串口入口改为等待读取线程在本轮就绪后交付的最新图像，避免消费已经排队的图像。独立零点试验的全处理帧年龄中位为 86.73 ms，P95 为 90.65 ms。三点试验均约 15 Hz，实测有效位只覆盖 ≤100 ms 的测量。

每次运行生成 `logs/track_*.csv` 和 `logs/link_*.csv`。track 表含图像帧号、墙钟时间、单调时钟、曝光核验结果、年龄、像素/参考/标定/厘米有效位和测量来源。link 表保存 Nano 位置帧序号和本地收发时间，以及遥测的板端时钟、位置、速度、目标、误差、倾角指令、PWM、控制状态、视觉有效位和故障位。软件估计杆角记录在 `beam_estimated_deg`。在此版协议中，0x81 帧头序号是板端遥测发送序号；载荷没有位置帧接收序号和单独的超时原因。固件在 LCD 的 Seq 栏显示最近接收序号，本次未记录人工读数。时间分析保留两端时钟域。

## 第一次 O 点回中尝试

在目标 0、起点约 +0.79 cm 下持续采集 90 秒，操作员确认释放钢珠并在 UART 页按一次 K1。Nano 发出 1432 帧，其中控制有效 997 帧，77 帧因过期失效。901 帧板端遥测全部为 IDLE，PWM 始终为 1722 µs，倾角指令始终为 0°。期间纸尺参考曾失效，随后 Nano 测到球去了负向，最小有效位置 −5.77 cm。板端最后保留约 +0.79 cm，且视觉有效位已清零。此段没有观测到 PD 执行或自动回中。

基线固件的 `BALL_TEST_ALLOW_AUTO` 默认为 0；在此编译配置下 UART 页 K1 无法进入 AUTO。即使本地使能已编入，按键瞬间无新鲜有效测量也会被拒绝。遥测约 10 Hz，缺少按键事件和已烧录固件的编译选项，因此这些记录不能单独确定拒绝原因。板端也会剔除大于 3 cm 的位置跳变，Nano 的有效 TX 不等同于板端接受。本次保留完整失败记录。
