# 纸尺身份复核及 O 点联调

工作分支 `feature/nano-static-control`，运行环境为 Nano 的 Python 3.6 / OpenCV 4.1.1。运行配置为 `config_static_control_ruler_c.json`，采用同一相机内参、纸尺原图、上缘剖面、方案 C 球心和 points 轨道投影。[静态模型及独立精度检查](../../static_reference_20261124/README.md)

## 最初失败的位置

120 秒记录中，2287 帧有 979 帧通过上缘，868 帧有厘米值，717 帧可用于控制。其余 1308 帧最早失败在 `RulerReference._guided_update / _confirm_rotation`：1067 帧没有足够可信的旋转提议，241 帧旋转复核后的相关峰弱或有竞争。原始配准失败后上缘和 points 都无法继续。该次记录没有 120 秒同步原片，不能逐帧认定照明或机位变化的物理原因。

另存的 60 帧补光原片复现了错误。第 36 帧右侧主模板的最佳位置从“17”跳到“18”，与另外两块的位移方向相反。全片左、中、右主块的最佳相关系数中位数分别为 0.847、0.707、0.603；右块竞争峰约 0.596。错误峰组三点残差中位数 24.13 px。与此前成功 O 点相比，球心投影上移约 54 px，不过正确数字仍位于原 ±96 px 搜索域内。照度和外观改变会影响峰值，当前原片不足以独立估计机械位移或现场照度。[错峰原图](patch_peaks.png)

## 修复及同帧对照

原主、备用模板均失去可信旋转匹配时，用同张参考图片上的三个数字小窗做当前帧的完整域匹配。强竞争峰仍否决结果。三块继续通过原有 0.85 相关系数、0.05 峰差、2.5 px 三点残差、实测上缘和 points 投影检查。旧配置、旧模型和旧检测器文件仍可独立运行。

| 同一 60 帧原片 | 上缘及纸尺身份确认 | 有效厘米值 |
|---|---:|---:|
| 原参考 | 0 | 0 |
| 新参考、正式入口 | 59 | 55 |

新三块最佳相关系数中位数 0.966、0.919、0.902。三点原图残差中位数 1.845 px，points 后为 1.196 px。4 帧等待钢珠身份确认，1 帧因纸尺竞争峰被拒绝。四处额外纹理共 240 次横向回投，最大差 0.98 px。遮挡及复制竞争峰的 30 个负控均被拒绝。该片用于选择数字区域，属于开发样片。

895 帧运动片在同灰度图、同时间戳下，实验 C 和正式入口均调用 895 次轨道检测、888 次物理 ROI 计算，585 个有效球心逐帧相同。使用两种入口本身的 MJPEG 解码方式时，灰度像素会有差别，候选与球心不总是一致，895 帧的轨道有效性判定一致。points 对当前观测的复核发生在配准成功后；失败段并非由第二次整图搜索引起。完整域竞争峰和上缘检查继续启用。固定参考点重复矫正的桌面节省量约 0.009 ms/有效帧，远小于板上匹配耗时。

历史真实刻度由新绑定重新拟合和验收。正式验证集 1312/1350，MAE 0.052 cm，最大绝对误差 0.282 cm。数字备用分支在这批刻度录像中没有触发；其跨刻度精度仍缺单独实物真值。文件解码开发回归中一段 −5 cm 仍有 0.454 cm 最大误差。

## 现场与控制动作

操作者确认无额外补光。5 ms、增益 0 在部分状态下过暗；相机回读相同也不能保证现场画面亮度相同。30 ms、增益 0 在 O 点取得过连续有效控制帧，但 13 cm 靠挡具时一个短测中 104 帧全部通过纸尺、没有有效球心。20 ms、增益 25 的 13 cm 原位短测有 32/32 帧同时检出尺和球。新配置在每次开相机时显式恢复后者，正式图像、模型和时间戳门控独立检查。

| 实机阶段 | 处理帧 | 纸尺有效 | 厘米有效 | 控制有效 |
|---|---:|---:|---:|---:|
| 原 120 秒基线 | 2287 | 979 | 868 | 717 |
| 原参考，固定 30 ms，O 点按键的 100 秒 | 1547 | 1547 | 1543 | 1496 |
| 新参考，20 ms，+1 cm 起始的 140 秒 | 2071 | 2039 | 2020 | 816 |
| 同一最终配置，重新摆放 O 点的 20 秒 | 298 | 298 | 294 | 190 |

最终 O 点测量中位 −0.105 cm、范围 −0.111～−0.085 cm，初始确认后 294 帧连续产生厘米值，仍有数据超龄。额外的离板掩膜缓存试验在 Nano 对三张原图循环时将尺匹配中位从 28.5 ms 降到 24.2 ms，尚未验证真实连续画面的时限收益，未接入控制。

现场各段的光照、摆放和时刻有别；前表的 60 帧才是同帧算法对照。140 秒中，控制无效的第一原因分别为 1218 帧超龄、30 帧姿态无效和 7 帧钢珠测量无效。曝光到读完中位 46.88 ms，参考匹配中位 34.25 ms，完整算法中位 55.00 ms，发送时年龄中位 102.20 ms、P95 112.93 ms。最长相邻有效发送间隔 10.97 秒。单纯降低增益至 16 的补充监测未改善时延。

- O 点按键时记录到两帧 AUTO，杆角指令 +0.026°、+0.062°，PWM 保持 1722 µs，随后发送了一帧 107.38 ms 的过期测量，下一帧遥测为 VISION_LOST。
- +1 cm 起始试验记录到 AUTO、板端 +1.004 cm、目标 0、杆角指令 −0.602°、PWM 1715 µs。后续两帧发送均为 stale，下一条遥测已为 IDLE、PWM 1722 µs。首次收到负位置约在 AUTO 采样 19.06 秒后，已处于 IDLE；最后有效位置约 −0.44 cm。这些位置无法证明由 PD 连续回中。两次试验分别收到 1000、1401 帧遥测，CRC 错误均为 0。没有板端按键事件的同步时间戳。
- 140 秒实测保留所有无效帧。高覆盖的厘米识别与满足发送时限的控制测量分别统计。杆角为软件指令；未独立测量真实杆角。

## 运行

在 Nano 独立部署目录中启动。第一条以监测模式运行；控制试验结束后发送无效位置，板端使用自身退出保护。

```sh
cd /home/jetson/ruler_check_1795524840725/Jetson
export OPENBLAS_CORETYPE=ARMV8 OPENBLAS_NUM_THREADS=1
port=/dev/serial/by-id/usb-wch.cn_CH32_CMSIS-DAP_B7AD8F061FFECDEFG-if01
python3 -B main.py --config config_static_control_ruler_c.json --serial "$port" --label ruler_monitor --duration 20
# 现场确认小车停车、目标 0 和 Vis=1 后，由操作员在 UART 页使能。
python3 -B main.py --config config_static_control_ruler_c.json --serial "$port" --uart-enable-valid --label ruler_return --duration 120
```

PC 与 Nano 各通过 301 项软件测试。下一项工程工作应优先压缩经核验的曝光到输出耗时，尤其是旋转复核。保留 100 ms 限制、同帧实测要求与 G3519 保护。[联合证据及逐帧记录](evidence.zip)
