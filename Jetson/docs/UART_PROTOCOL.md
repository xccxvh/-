# BV1 位置反馈协议（待 G3519 端适配）

115200 baud，8 数据位，无校验，1 停止位，无软/硬件流控，ASCII，LF 结束。
这是本次新增接口，**尚未确认与现有 G3519 固件兼容**。

格式：

```text
$BV1,SESSION,SEQ,CAPTURE_MS,AGE_MS,VALID,X_CM,CONFIDENCE,REASON*CRC16\n
```

| 字段 | 定义 |
|---|---|
| SESSION | 本次进程随机 uint32，会话标识，8 位十六进制 |
| SEQ | 每次编码递增的 uint32 十进制序号，含无效帧 |
| CAPTURE_MS | 采集线程读到帧时的单调时钟毫秒，uint32，约 49.7 天回绕；不是 G3519 时钟 |
| AGE_MS | 从采集线程收到帧到发送前编码的毫秒数，不含曝光和驱动内部缓冲、串口传输时间；未知为 -1 |
| VALID | 1=允许反馈，0=无效；监测模式始终为 0 |
| X_CM | 有效时带符号十进制，4 位小数；无效时空字符串，不是旧坐标，不是 0 cm |
| CONFIDENCE | 0..1000，只是检测算法评分，不是概率或正确性保证 |
| REASON | ok/clock/duplicate/stale/monitor/pose/vision/calibration/source_time |
| CRC16 | 4 位十六进制 CRC-16/CCITT-FALSE，计算 BV1 至 REASON（包括逗号），不包括 `$`、`*`、LF |

CRC 参数：poly=0x1021，init=0xffff，refin=false，refout=false，xorout=0。标准向量 ASCII `123456789` → `29B1`。
软件在采集时间不递增、年龄 >100 ms、预测位置、无效检测、未标定、姿态不符、非有限坐标时发送无效帧。
当前 Camera.timestamp_verified=False：无法证明驱动缓冲中的图像足够新，实时 VALID 始终为 0，即使显式启用也不会绕过。编码器的有效帧能力已在伪终端/软件测试验证；真实反馈需后续接入可信采集时间。

监测模式需显式 `--uart-enable-valid` 才解除；它不是硬件使能，不应使接收端自动进入控制。

接收端需要由 G3519 负责人实现：

1. 有限长度缓冲（建议 160 字节），`$` 重新同步，LF 收帧；格式/CRC/字段范围不符丢弃。
2. 使用 SESSION/SEQ 去重和拒绝乱序；会话变化时清除速度历史并退出自动控制，要求重新使能。序号回绕用 uint32 差值规则。
3. 只使用 VALID=1 且 X_CM 有限、范围合法、AGE_MS 合格的新测量。VALID=0 不更新速度/PD，按已验证失效策略处理。
4. 帧时间差仅由同一会话的 CAPTURE_MS 相减得到；不能把 Nano 与 MCU 绝对时间直接相减。长间隔或异常差值重置速度历史。
5. 以 MCU 本地接收时钟独立计时；无新有效数据须超时退出自动控制。建议起始评估 150 ms，须按现场延迟验证，不是已验证参数。
6. 本协议没有时钟同步/握手，无法单凭 CAPTURE_MS 检测链路缓存里的首个陈旧会话帧。禁止离线重放、禁止无界发送缓存；控制使能应清空接收缓冲并验证连续新帧。严格端到端新鲜度需要后续增加双方握手或时钟同步。
7. 最大倾角、角速度、机械限幅、急停、供电及视觉失效后的实际动作由 MCU 负责。不能仅依赖 Jetson 的退出无效帧。

Linux 发送端使用独占端口、单帧 10 ms 写入期限；失败关闭并退出，不重连、不重发。写入 OS 成功不等于 MCU 接收成功。
