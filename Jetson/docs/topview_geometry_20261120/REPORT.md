# 俯视机位畸变矫正 A/B 实测（2026-11-20）

这次四个静态点的两种模式都没有产生正确的有效钢珠位置。建议当前以原图采集及诊断为默认，把整帧矫正保留为可切换的实验配置。两种模式都未达到位置反馈要求。

## 实机配置

Nano 独立部署在 `~/topview_geometry_ab_20261120/vision`。在该目录运行以下任一命令。现场原始预览与直接采集程序共用一台 USB 摄像头，直采需释放设备。

```sh
OPENBLAS_CORETYPE=ARMV8 python3 main.py --config config_geometry_topview_undistorted_20261120.json --csv --label image
OPENBLAS_CORETYPE=ARMV8 python3 main.py --config config_geometry_topview_raw_20261120.json --csv --label raw
```

使用 1280×720、icspring USB 摄像头及此次人工锁定的焦点。焦点标识由现场设置记录，程序检查相机和焦点标识、分辨率、内参完整性以及文件 SHA。Nano 的原生 OpenCV 4.1.1 建图在 Brown 自检最大相差 0.147116333 px，容差 0.000122070312 px。关闭 OpenCV 优化后仍失败。新配置显式选择 projectPoints，每次启动用 OpenCV 将理想像素射线投影至原图，预计算两张浮点映射，再执行原有独立 Brown 校验。每帧走 CameraGeometry.prepare_frame 和 remap。默认 native 路径仍执行原检查。Nano 重新矫正参考原图后，与部署的矫正 PNG 在全部像素、全部颜色通道完全一致。

两份配置分别绑定本坐标系的参考 PNG、纹理框、上缘曲线、轨道左/零/右点及 ±5 cm 核心和 ±7 cm 搜索锚点。矫正配置在经过正式内参矫正的同一参考图上使用变换后的锚点，纹理框取投影四边形的内部区域。锚点沿用纸尺 ROI 的物理标签；厘米标定未启用。参考图上原始和矫正模式的搜索横坐标区间分别为 [241,1063]、[184.3,1126.9] px。对参考图施加 1° 图像内旋转及 (+12,−7) px 平移后两种模式都更新了 ROI；下一张空白图均返回无效。真实摆杆机械倾角未在本轮测试。

## 四点同帧识别

每段 120 帧，同一原始视频在 Nano 用 main.py 分别回放两次，统一 30 Hz 视频时间基准。O 与 −5 cm 使用既有俯视录像，+3 与 +5 cm 使用本轮 15 和 17 cm 刻度原片。误放纸尺 13 cm 的检查录像另存。每个点两种模式逐帧帧号及原片 SHA 已核对。固定工具在球旁可见。

| 位置 | 参考有效（原图 / 矫正） | 有效输出（原图 / 矫正） | 正确有效输出（原图 / 矫正） |
|---|---:|---:|---:|
| O | 118 / 113 | 43 / 0 | 0 / 0 |
| −5 cm | 120 / 120 | 0 / 0 | 0 / 0 |
| +3 cm | 120 / 120 | 0 / 0 | 0 / 0 |
| +5 cm | 120 / 120 | 0 / 0 | 0 / 0 |

在各段中帧确认真实钢珠中心和可见外轮廓，并用球体中心纹理逐帧跟随小幅位移。比较时把真实球体区域变换至相应坐标系，具有二维测量的输出再反投影核对。每个位置的配对 CSV 记录了真球位置、纹理匹配分、有效标志、身份判断、候选条件及耗时。配对图左原图、右矫正，绿色是真球区域，红线表示有效输出。O 点原图的 43 次输出都落在球左侧的固定工具区域。各点连续 120 帧均无正确测量，定位抖动没有可统计样本。

+3 cm 第 60 帧，真球横向范围内最大分量在原图为 10×12 px、矫正后为 7×13 px，均因宽度被拒。+5 cm 同一帧的原图分量为 12×25 px，宽高比被拒；矫正后为 3×24 px，因宽度被拒。该点矫正模式全部 120 帧中，与真球横向重叠的最大分量均被宽度门限拒绝。轮廓由多个局部分量组成，没有观察到矫正后形成可连续接受的完整球冠。分量统计按横向重叠判定，可能包含紧邻球体的固定工具。保留了原检测阈值及跟踪确认策略。

## Nano 直采性能

在纸尺 17 cm 保持同一位置，原图然后矫正，各运行一次 benchmark_live.py --mode A --duration 10。V4L2 实际协商 1280×720 MJPG，目标 30 FPS，无显示、无录像。两组使用同一台 Nano，同一预览暂停窗口。表中为该段实测，耗时包含首帧。轨道参考一栏为整个 rail.detect 调用。

| 指标 | 原图 | 整帧矫正 |
|---|---:|---:|
| 实际采集 FPS | 29.18 | 29.76 |
| 实际处理 FPS | 23.10 | 15.68 |
| 算法均值 / P95，ms | 41.59 / 42.87 | 62.93 / 67.91 |
| 几何处理均值 / P95，ms | 0.013 / 0.016 | 21.52 / 26.83 |
| 轨道参考均值 / P95，ms | 18.17 / 18.51 | 15.98 / 16.31 |
| 读帧返回至输出 P95，ms | 75.23 | 98.56 |
| 参考有效 / 处理帧数 | 232 / 232 | 157 / 157 |
| 钢珠有效 / 处理帧数 | 0 / 232 | 0 / 157 |

实机版本为 Python 3.6.9、OpenCV 4.1.1、NumPy 1.19.5。Nano 和电脑端软件测试分别通过 240 项。所有静态回放行的 cm_valid 和 feedback_valid 均为 0。仅校正测量点的 points 模式可以避免整帧 remap，但它沿用原图球冠检测，本轮未对其测速。后续可用遮挡更小的固定方式或自由滚动片段区分固定工具干扰和俯视球冠分割问题。

同目录的 static_results.json 含原片 SHA、每段汇总与拒绝原因。四组 *_pairs.csv 与 *_pairs.jpg 给出逐帧记录与代表画面。benchmark_raw.json 和 benchmark_undistorted.json 保留完整板端基准，nano_reference_check.json 和 roi_checks.json 保留坐标及失效检查结果。
