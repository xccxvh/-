# 高速钢珠候选检测实拍对照

**建议保留正式 Hough 链路，把 C（Hough 加配准帧差补搜）作为 Nano 的下一项像素实验。** 在留出的行驶录像中，C 找回了 24 个符合原有 12 px 球心标准的界内帧，其中 18 个来自快速组。共同检出的 388 帧，A 和 C 的球心相同。收益来自补回漏测和更早接续跟踪，尚不能据此提高厘米精度的声明。

## 方法与数据

基线为视觉分支 `d3a9be8` 和 `config_motion_cm_20261122.json`。A 保留该提交已启用的 Hough、运动模糊补搜、纸尺匹配和边界身份确认。按当时的处理帧号重放，三段 A 的有效位与原 Nano 日志逐帧一致，有效球心两轴最大差异均小于 10⁻⁹ px。

| 方案 | Hough 没有候选时的处理 |
|---|---|
| A | 使用原发布版本 |
| B | 用局部顶帽和形态学提取成对亮斑轮廓，再按当前图像球缘梯度拟合中心。检查两侧支撑、球径和法线方向分布，排除反光矩形挡具 |
| C | 用前后帧各自的纸尺相似变换对齐窄带，寻找新变暗的区域。在当前帧局部复核球缘和高光，检查圆周内外对比相对前帧是否新增。超过 150 ms 或参考失效后重新积累帧对 |
| D | 同时取 B 和 C。同一球径四分之一以内的两个中心去重，保留轮廓实测中心。分离的候选进入原跟踪器 |
| E | 在 D 的多个补充候选间，额外使用最近 100 ms 内的实测速度、原身份检查和原空间门限选择唯一匹配。无可信匹配时保留歧义 |

五组均优先保留原检测结果。原跟踪器在各组都使用运动预测和多帧确认。实验入口只发布当帧唯一、已确认的实测像素，使用原图坐标；生产入口和正式标定模型保持原版本。开源实现的具体借鉴及差异见[三个项目源码对照](upstream.md)。

开发片为固定球倾斜 `fixed_m5_final`、停车自由球 `parked_final`，另用较早的 `moving_fast_confirmed` 挑战快球。冻结后才对本轮留出的 `moving_final` 评分。固定、停车和留出行驶三段主对照分别含 895、871、895 个原始采集帧，共 2661 帧。它们已有历史标注。分别在原 Nano 的 691、809、677 个处理时刻运行有状态检测器，再按完整原始时轴独立从头跑一遍。固定球段自第 410 帧起只用图像中心标签，整份实验不以自由球轨迹推算物理厘米误差。

## 留出行驶片

高速定义为独立标注球心相对 ROI 中点的横向速度 ≥200 px/s。图像正确要求球心二维欧氏误差 ≤12 px。均值和最大误差包含所有有效且有中心标签的明确界内帧，包括超差帧。拖影标签是可见球心估读，无法给出曝光瞬间的物理中心。

## 复现

在仓库根目录执行。设 `data` 为本机 `jetson_nano/8` 的绝对路径，以新建目录保存日志。同一目标文件已存在时回放入口会拒绝覆盖。

```bash
data=/home/user/桌面/jetson_nano/8
for scene in fixed_m5_final parked_final moving_final; do
  python3 -B Jetson/candidate_fusion.py "$data/continuity_20261122/runs/$scene" "$data/recheck/logs/$scene.csv" --modes ABCDE
  python3 -B Jetson/candidate_fusion.py "$data/continuity_20261122/runs/$scene" "$data/recheck/all_frames/$scene.csv" --modes ABCDE --all-frames
done
python3 -B docs/vision_candidate_fusion/score.py --logs "$data/recheck/logs" --include-heldout-after-freeze --manual docs/vision_candidate_fusion/results/manual_identity.csv --out "$data/recheck/processed_scores"
python3 -B docs/vision_candidate_fusion/score.py --logs "$data/recheck/logs" --all-frames --include-heldout-after-freeze --manual docs/vision_candidate_fusion/results/manual_identity.csv --out "$data/recheck/full_scores"
```

逐帧评分、输入及源文件 SHA-256、成对差异、速度分组、回入事件和异常落点判读分别保存在[现场日程对照](results/frozen/processed/report.md)、[完整时轴对照](results/frozen/all_frames/report.md)、[冻结代码清单](results/frozen_code.sha256)及[附加录像结果](results/controls/challenge.csv)中。单位测试须在 Jetson 目录运行 `OPENBLAS_NUM_THREADS=1 python3 -B -m unittest discover -s tests -q`。

## Nano 实测

电脑端使用 OpenCV 4.8.1。板上单模式测试入口为 `python3 -B candidate_fusion.py RUN RUN/measurements.csv --modes C --live-seconds 30`，其中 RUN 为新的目录名。该入口录制全幅 MJPEG，保留全部读帧时间及实际处理日志。A 可在另一新目录采集，也可对 C 的同段视频按现场时序重放。

Nano 的 Python 3.6.9、OpenCV 4.1.1、NumPy 1.19.5 下，286 项软件测试通过。板上以 `OPENBLAS_CORETYPE=ARMV8 OPENBLAS_NUM_THREADS=1` 运行。最初未设置 ARMV8 的单独导入检查触发 illegal instruction；使用工程既有环境变量后导入、自检与完整测试均成功。安装目录为 `~/fusion_board_ZGqSeC/Jetson/`，原工程仍可用。
